# Agent Note: 模型选择器中的适配器推理强度滑杆

Status: implemented

[English](2026-08-14-effort-slider-in-model-picker.md) | 中文

## 问题

模型选择器已经接收每个确切模型由适配器提供的推理档位，但文字列表不利于快速理解有序强度，也不利于操作。控件必须继续适用于标识符不同或档位数量不同的提供方。

## 决定

`@deepseek-ai/dsh-client-ui-model-selection` 的 composer Effort 面板将适配器提供的有序档位显示为离散的原生 range 输入，并提供“更快”和“更聪明”端点。当前档位显示在标题和 `aria-valuetext` 中；滑杆支持键盘操作，并按适配器顺序工作，不解释 effort id。

滑杆变化继续调用现有的会话级 `session.selectModel` 路径，保持提供方和模型不变，仅提交所选的不透明推理强度 id。当模型没有配置默认值时，提供方默认值仍作为明确的第一个档位，因此省略 `reasoningEffort` 仍会恢复提供方行为。

这只改变呈现方式。模型选择器仍不拥有推理强度词表，不接受任意 id，并通过现有 Host／默认模型路径持久化被接受的选择。

## 考虑过的替代方案

**保留纯文字推理档位列表。** 它保持协议不变，但无法提供所需的有序强度控件和“更快—更聪明”的视觉方向。

**硬编码 `off`、`high` 和 `max` 三个滑杆档位。** 不同提供方的标识符和档位数量可能不同，硬编码会隐藏已支持的档位或发送无效 id。

**新增独立的客户端推理强度设置。** 第二个状态所有者可能与 Host 报告的会话选择分歧，也会绕过现有校验与持久化路径。

## 影响

composer 提供一个紧凑且支持键盘的推理强度控件，同时继续由现有 Host 与适配器负责请求、校验、持久化和模型能力。端点标签只描述视觉顺序，不宣称每个提供方的第一个或最后一个 id 具有固定语义名称。

无密钥组件测试和 declared-reasoning Web 场景验证滑杆暴露适配器的精确档位数量／顺序，并验证改变滑杆后仍会记录所选推理强度。
